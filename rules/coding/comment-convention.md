# 注释规范（COMMENT-001）

## 1. 目标
- 统一代码注释的分级要求与书写风格，让注释只提供代码本身无法表达的信息，提高注释信噪比与代码可维护性。

## 2. 适用范围
- 适用场景：TypeScript/JavaScript 项目中的变量、常量、函数、类、接口、类型、枚举的注释。
- 不适用场景：第三方库代码、自动生成的代码、配置文件。

## 3. 规则内容

### 3.1 总则

#### 3.1.1 注释三原则
1. 命名自解释优先：优先通过好的命名让代码自解释，注释是补充手段而非替代品。
2. 注释只补充代码无法表达的信息：为什么这么做、业务背景、注意事项、取值依据。
3. 每条注释必须提供名称之外的信息，复述名称的注释视为噪音。

#### 3.1.2 注释分级

| 级别 | 适用对象 |
|---|---|
| 必须 | 导出的函数、类、接口、类型别名、枚举；常量；含义不直观的变量与对象属性；复杂逻辑块；魔法数字；业务规则；workaround |
| 建议 | 内部工具函数；用法不直观的代码段 |
| 禁止 | 复述名称的注释（如 `/** 用户名称 */ const userName`）；注释掉的代码；与代码不一致的注释 |

#### 3.1.3 注释格式
- 所有注释必须使用多行注释格式（`/** ... */`），包括函数体内的实现说明。
- 禁止使用单行注释（`//`）作为注释。

### 3.2 变量与常量注释规范

#### 3.2.1 普通变量
- 见名知义的普通变量（如 `userName`、`isLoading`）无需注释；为其编写复述性注释视为不合规。
- 含义不直观的变量必须使用 `/** ... */` 注释说明用途或数据来源。

#### 3.2.2 常量
- 常量必须使用 `/** ... */` 注释。
- 注释必须说明常量的含义与取值依据（如为什么最大重试次数是 3），禁止只复述名称。

#### 3.2.3 对象属性
- 对象字面量中仅含义不直观的属性需要注释。
- 接口（`interface`）属性必须逐个注释，接口属于公开契约（见 3.4）。

### 3.3 函数注释规范

#### 3.3.1 导出函数
- 导出函数必须使用完整的 JSDoc 注释，位于函数声明上方，包含：
  - 首行功能描述（必须，一句话说明做什么）
  - `@param`：每个参数必须标注（如有参数）
  - `@returns`：返回值说明（如有返回值）
  - `@throws`：异常说明（如可能抛出异常）
- `@description`：建议，仅在首行描述不足以说明行为或副作用时使用。
- `@example`：建议，仅对公开工具函数、用法不直观的函数使用；简单函数无需。

#### 3.3.2 简单函数豁免
- 同时满足以下条件的函数可不写注释：无参数、无返回值、实现直观（如事件 handler、getter）。
- 若为简单函数编写注释，仍必须使用 `/** ... */` 格式，禁止堆砌完整 JSDoc。

#### 3.3.3 参数说明
- 每个参数必须使用 `@param` 标注。
- TypeScript 项目中参数说明格式为 `@param 参数名 - 参数说明`，不带 `{类型}` 标注（类型以函数签名为准）。
- 对象参数的属性必须使用 `@param 对象名.属性名 - 说明` 嵌套说明。

#### 3.3.4 返回值说明
- 有返回值的导出函数必须使用 `@returns` 标注。
- 返回值说明格式：`@returns 返回值说明`。

#### 3.3.5 函数体内注释
- 复杂逻辑块、业务规则、workaround 必须在函数体内使用 `/** 说明 */` 块注释解释原因。
- 函数体内同样禁止使用单行注释（`//`）。

### 3.4 类、接口与类型注释规范

#### 3.4.1 类注释
- 导出的类必须使用 `/** ... */` 注释说明用途。
- 类的私有成员仅在含义不直观时注释。

#### 3.4.2 接口注释
- 导出的接口必须使用 `/** ... */` 注释说明用途。
- 接口属性必须逐个添加注释。

#### 3.4.3 类型别名注释
- 导出的类型别名必须使用 `/** ... */` 注释说明用途。

### 3.5 枚举注释规范

- 枚举声明与每个枚举属性必须使用 `/** ... */` 注释，说明用途与含义。
- 枚举的三件套定义（Enum + LabelMap + Options）及配套注释要求以 ENUM-001（`enum-definition.md`）为准，本节仅约定注释格式，不重复定义。

### 3.6 禁止事项
- 禁止使用单行注释（`//`）作为注释。
- 禁止复述名称的注释（如 `/** 用户名称 */ const userName`）。
- 禁止注释与代码不一致。
- 禁止保留注释掉的代码。
- 禁止为简单函数堆砌完整 JSDoc。
- 禁止在 `@param` 中重复标注 TypeScript 签名中已有的类型。

## 4. 输出要求
- 注释必须使用中文。
- 注释必须使用多行注释格式（`/** ... */`）。
- 注释必须遵守 3.1.2 的分级要求：必须项不缺失，禁止项不出现。
- 导出函数的 JSDoc 结构顺序：功能描述 → `@description`（可选）→ `@param` → `@returns` → `@throws`（可选）→ `@example`（可选）。

## 5. 示例

### 合规示例

#### 变量与常量
```ts
const userName = 'John';
const isLoading = true;

/**
 * 最大重试次数
 * 依据网关平均抖动恢复时间设定为 3 次
 */
const MAX_RETRY_COUNT = 3;

/** 后端返回的原始响应，未做字段清洗，使用前需校验 */
const rawResponse = await fetchUser();

const userInfo = {
  id: 1,
  name: 'John',
  /** 年龄单位为周岁，由身份证信息推算 */
  age: 25,
};
```

#### 导出函数
```ts
/**
 * 获取用户信息
 *
 * @param userId - 用户ID
 * @returns 用户信息对象
 * @throws 当用户不存在时抛出 NotFoundError
 */
function getUserInfo(userId: number): UserInfo {
  /** ... */
}

/**
 * 创建新用户
 *
 * @param options - 创建选项
 * @param options.name - 用户名称
 * @param options.age - 用户年龄
 * @returns 创建的用户对象
 * @example
 * const user = createUser({ name: 'John', age: 25 });
 */
function createUser(options: { name: string; age: number }): User {
  /** ... */
}
```

#### 简单函数（豁免注释）
```ts
function handleClose() {
  setVisible(false);
}
```

#### 类、接口与类型
```ts
/**
 * 用户服务类，负责用户相关的业务逻辑
 */
class UserService {
  /**
   * 获取用户详情
   *
   * @param userId - 用户ID
   * @returns 用户详情
   */
  getUserDetail(userId: number): UserDetail {
    /** ... */
  }
}

/**
 * 用户信息接口
 */
interface IUserInfo {
  /** 用户ID */
  id: number;
  /** 用户名称 */
  name: string;
  /** 用户邮箱 */
  email: string;
}

/**
 * 用户角色类型
 */
type UserRole = 'admin' | 'user' | 'guest';
```

#### 枚举（格式示例，完整要求见 ENUM-001）
```ts
/**
 * 用户状态枚举
 */
enum UserStatusEnum {
  /** 激活状态 */
  Active = 'Active',
  /** 已禁用状态 */
  Disabled = 'Disabled',
}
```

### 不合规示例

```ts
// 问题1：复述名称的注释，未提供名称之外的信息
/** 用户名称 */
const userName = 'John';

// 问题2：常量注释只复述名称，缺少取值依据
/** 最大重试次数 */
const MAX_RETRY_COUNT = 3;

// 问题3：为简单函数堆砌完整 JSDoc
/**
 * 处理关闭
 *
 * @description 点击关闭按钮时触发
 * @example
 * handleClose();
 */
function handleClose() {
  setVisible(false);
}

// 问题4：@param 重复标注 TypeScript 签名中已有的类型
/**
 * 获取用户信息
 *
 * @param {number} userId - 用户ID
 * @returns 用户信息对象
 */
function getUserInfo(userId: number): UserInfo {
  /** ... */
}

// 问题5：注释与代码不一致
/** 用户年龄 */
const userName = 'John';

// 问题6：保留注释掉的代码
/** const legacyHandler = () => submit(form); */
function handleSubmit() {
  submit(form);
}

// 问题7：函数体内使用单行注释
function calcPrice() {
  // 满减规则：超过 100 减 20
  return price > 100 ? price - 20 : price;
}
```

## 6. 自检清单
- [ ] 每条注释是否提供了名称之外的信息
- [ ] 导出的函数、类、接口、类型、枚举是否都有注释
- [ ] 导出函数的 `@param`、`@returns`、`@throws` 是否按适用情况齐全
- [ ] 常量注释是否说明了含义与取值依据
- [ ] 是否存在复述名称的注释
- [ ] 是否存在注释掉的代码
- [ ] 是否为简单函数堆砌了完整 JSDoc
- [ ] `@example` 是否仅用于公开工具函数或用法不直观的函数
- [ ] 注释是否全部使用中文多行注释（`/** ... */`）
- [ ] 注释是否与代码保持一致
