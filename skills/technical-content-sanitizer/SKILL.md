# Technical Content Sanitizer

## 目标

将可能包含企业内部信息的研发资料，安全地整理为适合公开分享的技术内容，同时尽可能保留技术事实、问题分析过程和解决方案。

本 Skill 定义审查规范、判断边界和处理流程，不实现专用文件解析器、OCR 或脱敏程序。依靠模型自身能力理解用户提供的文件和内容；对无法读取、无法识别或无法完整理解的部分明确披露，不得声称已经审查。

## 默认配置

- 默认工作模式：**B — 脱敏 + 技术博客重构**。
- 默认脱敏尺度：**Conservative（保守脱敏）**。
- 默认映射策略：**Consistent Replacement（统一替换名称）**。
- 默认确认机制：**Selective Confirmation（选择性确认）**。自动处理判断明确且处理方案明确的事项；仅对不确定事项、存在实质歧义的高风险决策或可能改变技术含义的处理请求用户确认。
- 原始资料只读；所有输出写入独立位置，不覆盖输入文件。
- 持久化配置的新增、修改和删除必须获得用户明确授权。
- 不自动发布内容；所有最终产物都需要用户人工审核。

## 工作模式

用户明确指定模式时按指定模式执行；未指定时使用模式 B。

| 模式 | 行为 | 主要交付物 |
|---|---|---|
| A — Sanitization Only | 保持原文结构和表达，进行必要的敏感信息处理；除脱敏所必需外不主动改写 | 脱敏文档、安全审查报告、变更记录 |
| B — Sanitization + Blog Rewrite | 先审查和脱敏，再将内容重构为连贯的公开技术文章 | 公开技术文章、安全审查报告、变更记录 |
| C — Audit Only | 只审查，不修改输入内容，不生成脱敏版 | 安全审查报告和处理建议 |

三种模式必须使用同一套审查标准、分类体系、风险等级、组合风险判断和脱敏策略。模式只能决定审查结果之后执行什么动作，不得影响审查结论。

## 核心执行要求

1. 理解单份或多份关联资料；多份资料应作为同一审查范围联合分析，关注跨文件关联风险。
2. 先完成统一的原始资料审查，再根据模式执行后续动作。
3. 将发现记录为统一的 Review Result，区分 Risk Level、Confidence、推荐 Strategy、实际 Action 和处理 Status。
4. 对明确敏感且处理方案明确的信息自动处理；对明确安全的信息保留；对不确定或存在实质歧义的信息请求确认或采用明确标注的保守方案。
5. 保护技术事实，不得编造参数、版本、环境、因果关系、实验结果或结论。
6. A、B 模式完成处理后，必须对最终文档执行完整复审。C 模式不修改原文，只输出审计结论。
7. 审查报告和变更记录本身也不得泄露原始敏感值。
8. 原始文件保持不变。若需要落盘，使用独立输出目录；不得覆盖已有文件，发生命名冲突时选择新名称或询问用户。
9. 仅在用户明确授权后，才写入或修改外部持久化配置。
10. 不得将“未发现问题”描述为绝对安全或发布授权。

## 上下文管理

支持三种上下文：

- **Global Rules**：通用规则，供所有任务使用。
- **Project Profiles**：项目专属实体映射和额外限制，作为后续扩展能力。
- **Task Context**：当前任务内的临时发现、跨文件关联和用户确认结果，任务结束后不自动持久化。

建议的外部配置路径为 ~/.config/technical-content-sanitizer/，但实际路径应可配置。第一版只依赖内置审查标准、可选 Global Rules 和 Task Context；没有任何外部配置时也必须完整运行。Project Profiles 第一版只预留概念，不要求实现自动管理。

外部配置可能包含真实内部名称及映射关系，应按敏感资料保护。不得自动同步、上传或提交到业务仓库。持久化配置的读取、写入边界和授权要求见 [references/mapping-rules.md](references/mapping-rules.md)。

## 文件理解边界

不限定输入文件类型，不为 Markdown、Word、PDF、代码、日志、图片或架构图实现专用解析流程。依靠模型自身可用能力分析内容。若某部分无法读取、内容缺失或图像细节无法辨认，必须在报告中说明受影响的范围，并将审查状态标记为 Incomplete；不得将未检查内容视为通过。

除非用户明确授权且运行环境符合组织要求，不要将内部资料发送给外部服务、第三方连接器或其他未批准的处理环境。

## 完成前检查

确认：
- 三种模式的初始审查结果遵循同一标准。
- 所有发现均有位置或可定位的上下文、判断依据、风险等级、置信度和处理状态。
- 未把不确定信息当作 Low 或安全信息。
- 映射在整批资料及最终文档中一致。
- 技术事实、因果关系和证据边界未被改变。
- A、B 的最终产物已经完整复审。
- 报告、变更记录和输出文件没有重新暴露敏感信息。
- 未覆盖原始资料，未未经授权持久化配置。
- 发布状态准确，且明确说明仍需人工审核。

## 交付

根据所选模式生成对应产物，并说明输入范围、使用的模式、审查范围、未解决事项、处理限制和最终发布状态。输出格式遵循 [references/output-format.md](references/output-format.md)。
