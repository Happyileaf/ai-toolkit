# 统一审查标准（Shared Review Standard）

本文件是 Technical Content Sanitizer 的唯一审查标准。模式 A、B、C 必须使用同一套审查步骤、敏感信息分类、风险评估、组合风险判断和脱敏策略。其他参考文件只细化本标准，不得另行创建模式专属标准。

## 1. 审查目标

判断输入资料在面向公开互联网发布时可能暴露的企业、人员、客户、基础设施、业务、技术资产和安全信息，并提出能够降低风险且尽量保留技术价值的处理方案。审查不是法律意见、企业授权或绝对安全认证。

## 2. 统一审查维度

1. **Direct Identifiers**：是否直接识别企业、个人、客户、项目或内部系统。
2. **Confidential Information**：是否暴露非公开业务数据、技术资产、内部架构或运营信息。
3. **Credentials and Access**：是否包含凭证、访问入口、权限信息或可利用配置。
4. **Exploitability**：公开后是否可能帮助未授权访问、攻击或规避安全控制。
5. **Linkability**：是否能与公开资料或其他文档关联，识别特定主体。
6. **Aggregation Risk**：多条低风险信息或多份文件组合后是否产生更高风险。
7. **Technical Integrity**：处理是否会改变技术事实、因果关系、参数或结论。
8. **Review Completeness**：输入是否已被充分读取和理解，是否存在未审查区域。

## 3. 统一处理顺序

所有模式的初始审查严格执行相同顺序：

1. 明确审查范围，识别文件之间的关联。
2. 理解技术背景并提取可验证的技术事实。
3. 识别显式敏感信息和隐式敏感信息。
4. 按分类目录归类每项发现。
5. 评估每项发现的 Risk Level 和 Confidence。
6. 分析单项风险及组合风险。
7. 为每项发现选择建议 Strategy。
8. 形成统一的 Raw Review Result。
9. 根据用户确认和默认策略执行或仅报告。
10. A、B 完成处理后，对最终产物执行同一标准的完整复审。

## 4. 风险与置信度分离

每项发现必须分别记录 **Risk Level**（信息公开后的潜在影响）和 **Confidence**（模型对其敏感性质判断的把握）。两者不可合并为一个分数。

## 5. 统一决策规则

| 识别结论 | 处理原则 |
|---|---|
| 明确敏感，处理方案明确 | 自动执行安全处理 |
| 明确安全且无组合风险 | 保留 |
| 不确定但可用保守方式安全替换 | 采用保守处理，并在报告中标注 |
| 不确定且不同处理会影响事实或文章含义 | 请求用户确认 |
| 高风险内容的保留、披露或弱化存在实质决策 | 必须请求用户确认；不得默认保留 |
| 无法可靠审查或无法生成安全版本 | 标记 Incomplete 或 Blocked |

明确的凭证泄露可以自动删除，不需要为了删除而打断用户。

## 6. 模式一致性

模式 A、B、C 对相同输入、相同上下文和相同配置，必须得到一致的初始 Findings、Risk Level、Confidence 和建议 Strategy。模式差异仅体现在后续动作：

- A：按计划处理，尽量保留原文结构。
- B：按计划处理并重构文章，随后进行新的最终审查。
- C：只输出审查发现和建议，不修改输入。

B 的最终审查允许发现重构后新引入或重新组合的风险；这不应反向改写初始审查记录。
