# 输出规范（Output Format）

## 1. 交付物

### 模式 A — Sanitization Only

1. 脱敏文档：尽量保留原始结构。
2. 安全审查报告：记录发现、风险、处理结果、剩余风险和发布状态。
3. 变更记录：记录删除、替换、泛化、合成和重写等变更，不暴露完整敏感原文。

### 模式 B — Sanitization + Blog Rewrite

1. 公开技术文章：适合继续编辑和人工发布。
2. 安全审查报告：包含初始审查与最终复审结果，区分两轮发现。
3. 变更记录：记录重要内容变更及其对表达、结构和技术事实的影响。

### 模式 C — Audit Only

1. 安全审查报告：包含发现、风险等级、置信度、位置、判断依据、建议策略、待确认事项和完整性限制。
2. 不修改原文，不生成脱敏副本，不生成已执行的变更记录。

## 2. 安全审查报告字段

至少包括审查范围和输入资料清单、工作模式、审查标准、审查完整性、无法读取的部分、整体风险等级、Findings、组合风险分析、用户确认事项及结果、最终产物复审结论（A/B）、未解决风险和发布状态、人工审核提示。

每条 Finding 至少包含 ID、类别、位置、证据摘要、Risk Level、Confidence、建议 Strategy、实际 Action 和 Status。

## 3. 变更记录字段

至少包括 Change ID、对应 Finding ID、原始资料位置、变更类型、变更后表达摘要、变更原因、是否影响技术语义、是否经用户确认。默认不记录完整敏感原文、密钥、Token、个人数据或完整内部映射。使用安全摘要、局部遮蔽值或实体 ID 定位。

## 4. 敏感信息展示规则

不在报告或变更记录中复制有效凭证，不完整展示个人身份信息，不输出完整内部映射表。报告应说明类别、位置和风险原因，避免为了证明发现而重现泄露。必要时使用脱敏片段，例如 10.x.x.[redacted] 或 [credential removed]。

## 5. 文件输出位置

不覆盖输入文件。在用户指定的独立目录输出。用户未指定目录时，使用当前工作空间内独立的 sanitized-output/ 目录；如果无法安全确定工作空间或目录已存在且会发生覆盖，询问用户或创建不冲突的新目录。不在业务仓库中自动创建 Project Profile 或 Global Rules，不自动发布或推送公开文章。

## 6. 报告语言

默认使用用户当前对话语言。公开技术文章沿用用户指定语言；用户未指定时沿用源资料主要语言。技术术语、代码符号、API 名称和配置键保持准确。
