# 执行流程（Execution Workflow）

## 1. 模式选择

用户指定 A、B、C 时按指定模式执行；未指定时默认 B — Sanitization + Blog Rewrite。

## 2. 输入范围确认

识别用户提供的全部资料及关联关系。多份文件如属于同一项目、故障或技术主题，应联合审查。若范围不清楚且会影响审查完整性，只询问最关键的澄清问题。

不限制文件类型，不运行专用解析器或 OCR。依靠模型可用能力理解文件；不能读取的部分必须披露。

## 3. 加载上下文

加载 Skill 内置的统一审查规则；如有可用且用户允许访问的 Global Rules，则读取并应用；如有 Project Profiles，则只在可用且适用时读取，第一版不依赖它；创建本次 Task Context，记录实体、跨文件关系、确认结果和不确定项，不自动持久化。

## 4. 原始资料审查（所有模式完全相同）

1. 理解资料和技术背景。
2. 提取技术事实、推断和未知项。
3. 识别八类显式和隐式敏感信息。
4. 检查单项风险和组合风险。
5. 为每项 Finding 评估 Risk Level、Confidence。
6. 制定 Sanitization Strategy。
7. 形成统一的 Raw Review Result。
8. 自动处理明确事项；对不确定或实质歧义请求确认。

不要因工作模式不同而改变初始审查结果。

## 5. 模式执行

### A — Sanitization Only

按审查计划处理敏感内容，尽量保留原文结构、段落和技术表达。不进行与脱敏无关的润色或博客化重写。生成脱敏文档、审查报告和变更记录。

### B — Sanitization + Blog Rewrite

按审查计划先处理敏感内容，在不改变技术事实的前提下重构为适合公开分享的技术博客。可优化标题、结构、可读性和解释顺序；不补造事实或验证结果。生成公开文章、审查报告和变更记录。

### C — Audit Only

不修改原始资料，不生成脱敏版本。输出审查发现、风险评估、处理建议、待确认事项和完整性限制。审查报告本身不得复述完整敏感值。

## 6. 用户确认

集中列出真正需要用户决策的事项，说明需要确认的内容类别和位置、风险及判断依据、可选处理策略及其对技术语义的影响、推荐的保守方案。不要询问已能从上下文明确判断的事项。明确的凭证移除等安全动作直接执行。

用户确认仅适用于当前明确范围，不自动修改其他类似信息，也不等同于授权企业公开或持久化配置。

## 7. 最终复审

A、B 的最终文档必须重新执行统一审查标准，检查原始敏感信息是否残留、重构是否引入新的敏感信息、组合风险是否仍存在、名称映射是否一致、技术事实和证据边界是否保持、报告和变更记录是否泄露原始敏感内容、文件是否完整可读。C 不修改输入，不执行最终文档复审；但审查报告自身仍需避免敏感信息泄露。

## 8. 交付与持久化

按输出规范生成产物；原始资料只读，输出到独立位置；不覆盖已有文件；报告明确标注未解决事项和审查限制。只有用户明确授权时，才保存、更新或删除 Global Rules / Project Profiles。
