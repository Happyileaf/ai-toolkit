# 场景：input-boundary（输入边界处理）

## 检查目标

识别通用输入处理中的明确边界缺陷，例如空值访问、类型假设错误、边界索引错误、格式解析失败未处理和用户输入导致的运行时异常。

本场景只处理通用技术边界，不推断业务字段的合法值、长度、格式或必填规则。

## 风险特征

- 直接访问可能为 null/undefined 的对象属性或数组元素。
- 将外部输入直接断言为特定类型而未验证。
- 空数组、空字符串、零值、负数或极大数值触发错误计算。
- parse、JSON、日期或数值转换对无效输入没有处理。
- slice、substring、索引、分页边界出现 off-by-one。
- 输入组件返回的值类型与处理代码假设不一致。
- 可选字段缺失导致渲染或事件处理崩溃。

## 检查方法

1. 识别输入来源：用户输入、URL/query、表单控件、外部数据、storage 或 API 返回。
2. 检查数据类型、空值、长度、范围和格式的技术假设。
3. 沿输入进入计算、渲染、索引和序列化的路径检查边界。
4. 确认边界是否由上游 schema、组件契约或运行时校验保证。
5. 识别异常输入是否能导致崩溃、错误计算或错误访问。
6. 只验证通用技术安全性，不决定业务字段应接受什么值。

## 正确性约束

- 可选或外部输入必须按实际类型和可空性安全处理。
- 空值、空集合和合法边界值不得导致意外运行时异常。
- 类型转换失败应按现有错误处理约定处理，不得静默产生误导数据。
- 不能把 0、false、空字符串等合法 falsy 值误判为缺失，除非现有契约明确如此。
- 不得擅自增加业务校验或改变错误提示。

## 排除条件

- 需要产品定义业务字段格式、取值范围、必填规则或错误提示。
- 需要决定金额、数量、日期、状态等业务值的合法范围。
- 需要新增安全策略、权限规则或服务端校验。
- 只有潜在输入风险，没有可证明的错误路径。

## 修复原则

- 优先依据现有类型、schema 和组件契约增加局部保护。
- 保留合法 falsy 值，避免用宽泛 truthy 判断替代明确空值判断。
- 解析失败时沿用现有错误处理路径，不得擅自吞掉错误或伪造默认业务值。
- 不为消除类型错误而使用 any 或不安全断言掩盖问题。
- 不定义资料中不存在的业务合法值。

## 验收标准

- null/undefined、空集合和格式异常输入不会导致已确认的运行时错误。
- 合法边界值（包括 0、false、空字符串，若契约允许）行为保持正确。
- 业务校验、错误文案和默认值语义未被擅自改变。
- 正常输入路径结果与修复前一致。

## 关联场景

- async-loading：异步数据到达前可能存在空值边界。
- component-lifecycle：组件初始化或卸载期间输入数据可能暂时不可用。
