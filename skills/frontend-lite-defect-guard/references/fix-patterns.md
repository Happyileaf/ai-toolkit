# 常见修复模式参考

本文件提供常见修复思路，不是可以机械套用的代码模板。必须先确认项目框架、资源所有权和业务语义。

## 1. Synchronous Guard（同步互斥保护）

适用于确认同一操作在进行中不得再次启动的情况。

- 在第一个 await 之前同步设置互斥标记。
- 检查所有动作入口是否经过同一保护边界。
- 在正确的终态释放标记。
- 如果不同实体可并行，锁必须按实体或操作隔离。
- UI disabled 可作为反馈，但不一定能替代同步互斥。

## 2. Timer Lifecycle（计时器生命周期）

适用于已存在 debounce/throttle 但 timer 生命周期错误的情况。

- 保留既有延迟参数与 leading/trailing 策略。
- 新任务到来时按现有策略清理旧 timer。
- 在组件资源所有权结束时清理 timer。
- 明确回调读取的是调用时数据还是执行时最新数据。

## 3. Request Identity（请求身份标识）

适用于最新请求结果应覆盖旧请求结果的明确场景。

- 为每个请求分配递增序号或稳定身份。
- 只有当前有效身份可以写入状态或触发副作用。
- success、error、finally 均检查身份。
- AbortController 可作为资源优化，但仍需按场景评估响应身份检查。
- 不用于需要合并所有请求结果的业务。

## 4. Async State Finalization（异步状态收尾）

适用于某个异步流程在异常路径遗漏清理的明确问题。

- 使用 try/finally 保证必要清理执行。
- 确认 finally 清理的是当前操作拥有的状态。
- 多请求共享状态时，不可简单地由任意一个请求结束就设为 false。
- 不擅自改变旧数据保留或错误展示策略。

## 5. Lifecycle Cleanup（生命周期清理）

适用于组件拥有的资源未正确释放。

- 注册与 cleanup 使用相同资源句柄。
- 依赖变化时先清理旧订阅或监听，再建立新订阅。
- 异步回调需要检查任务或实例是否仍有效。
- 不取消所有卸载后仍需完成的业务任务。

## 6. Input Guard（输入保护）

适用于明确的空值、类型和边界运行时错误。

- 使用契约支持的类型和可空性检查。
- 保留合法 falsy 值。
- 转换失败沿用现有错误处理约定。
- 不推断业务合法值或擅自添加字段校验。

## 7. 通用修复禁区

- 不以增加防抖代替请求竞态保护。
- 不以取消请求代替过期响应校验。
- 不以按钮 disabled 代替所有重复入口的互斥。
- 不用一个全局 loading 布尔值管理多个独立并发操作。
- 不用 mounted 标记掩盖资源泄漏或错误所有权。
- 不以宽泛 try/catch 吞掉异常。
- 不通过 any、非空断言或类型断言绕过真实边界问题。
