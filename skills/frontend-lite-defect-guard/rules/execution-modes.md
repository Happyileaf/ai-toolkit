# 执行模式与修复准入

## 1. Report Only

只检查和报告。不得修改业务代码、测试代码或配置。

## 2. Report + Confirm（默认）

完成全部检查并输出报告后，等待用户确认。用户可以选择：
- 修复全部 Confirmed 问题。
- 只修复指定问题 ID。
- 修复全部但排除指定 ID。
- 暂不修复。

Potential 问题默认不自动修复。即使用户要求修复，也应先补足证据或说明不确定性。

用户的确认只授权报告中明确的问题和修改范围。修复过程中发现的新问题需要另行报告和授权。

## 3. Report + Auto Fix

只有用户明确选择此模式时使用。自动修复仅限满足所有准入条件的 Confirmed 问题：
- 根因明确。
- 修复模式成熟、确定。
- 影响局部。
- 不需要推测业务意图。
- 不改变既有业务语义。
- 有可执行验证。
- 不覆盖用户已有修改。

不满足条件的问题只报告。

## 4. 测试代码权限

获得修复授权后，可以新增或调整针对当前缺陷的局部测试。此权限不等于允许扩大业务代码修改范围，也不允许重构测试基础设施。

## 5. 失败与停止

- 单个独立问题失败：停止该问题，其他独立问题可继续。
- 前置问题失败：停止依赖它的后续问题。
- 出现用户修改冲突：停止受影响区域。
- 需要改变业务语义：停止并请求用户决策。
- 无法安全回滚：保留现状并说明，不冒险操作。
