# 职责范围规则

## 1. 适用范围

只检查前端应用代码中局部、明确、可验证的小型缺陷。候选问题应满足：高频、低复杂度、模式明确、影响局部、修复可预测。

典型目标包括用户交互处理、异步请求、组件状态和通用输入处理。

## 2. Target Scope 与 Context Scope

- **Target Scope**：用户明确指定的文件、目录、组件、页面或功能，是唯一允许主动扫描的范围。
- **Context Scope**：为理解目标代码所必需读取的类型定义、调用方、被调用方、共享 Hook、请求封装、配置或测试。

Context Scope 仅用于理解和验证，不自动成为扫描范围或修改范围。若在上下文中发现疑似问题，记录为范围外观察；除非用户扩大范围，否则不主动分析或修改。

未明确指定范围时，使用当前请求直接涉及的最小合理范围，不默认全仓库扫描。

## 3. 场景匹配

逐项判断以下场景是否适用：
- duplicate-submit
- debounce
- request-race
- async-loading
- component-lifecycle
- input-boundary

场景不适用时记录 Not Applicable，不为追求覆盖而强行检查。

## 4. 排除条件

以下问题不处理：
- 需要理解复杂业务规则才能判断正确行为。
- 需要跨服务、跨页面或跨系统协调才能修复。
- 需要产品或设计决策才能确定预期结果。
- 需要重构较大范围代码才能消除。
- 只有风格、可读性或性能偏好，没有错误行为证据。
- 涉及安全、权限、支付、交易等高风险业务规则，且修复需要推断意图。

## 5. 范围扩展

只有用户明确授权才扩大 Target Scope。修复过程中发现相邻代码问题时，先记录，不顺手修改。若原问题根因确实位于 Target Scope 外，说明所需的最小扩展范围并等待授权。
