# 输入输出一一对应规则

## 1. 强制规则

输入问题清单与输出核实结果必须严格一一对应：

- 每个输入问题必须有一个独立输出结果。
- 每个输入问题只能对应一个输出结果。
- 不允许遗漏。
- 不允许重复输出。
- 不允许合并问题条目。
- 不允许因重复或相同根因而减少输出数量。
- 默认保留输入顺序。
- 保留原始问题编号或标识；没有原始编号时，按输入顺序分配本次报告编号。

这是报告完整性约束，优先级高于去重、压缩和报告简洁性。

## 2. 数量与映射校验

设输入问题集合为 I，输出核实结果集合为 O。

必须满足：

N_input = N_output

并且每个输入问题恰好对应一个输出结果：

对于每个输入问题 i，Count(Output(i)) = 1。

数量相等只是必要条件，还必须检查映射关系，防止某个问题被重复输出而另一个问题被遗漏。

## 3. 重复问题与相同根因

允许：
- 标记完全重复的问题。
- 标记可能共享根因的问题。
- 复用相同的代码阅读和分析过程。
- 在详情中引用共同证据。
- 通过 Related Issues 标记关联问题。

禁止：
- 将多个输入问题合并为一条输出记录。
- 只输出一个共同结论代替多个独立结论。
- 因为描述相同而跳过某个问题的核实。
- 直接复制一个问题的 Verdict 给其他问题而不核实各自场景。

即使问题完全重复，也必须为每个原始条目保留独立结果。可以说明其与另一个编号内容重复，并复用分析，但应确认其原始定位和上下文是否一致。

相同根因也不保证 Verdict 相同：不同代码位置可能具有不同触发条件、保护机制或业务影响。

## 4. 输入顺序与编号

- 默认按输入顺序输出列表和详情。
- 原始编号存在时，原样保留。
- 原始编号缺失时，分配 01、02、03 等报告编号。
- 原始编号重复或冲突时，额外分配唯一 Report No.，同时保留原始 ID。
- 不得重新排序以便按 Verdict 分组而破坏原始对应顺序。可以在摘要中统计各状态数量。

## 5. 最终完整性检查

交付报告前必须逐项核对：
1. 输入总数。
2. 输出列表记录数。
3. 输出详情数量。
4. 每个原始 ID 是否恰好出现一次。
5. 没有原始 ID 的问题是否按输入位置全部映射。
6. 是否有遗漏、重复或合并。
7. 每个输出是否有且只有一个 Verdict。
8. 四类 Verdict 的数量之和是否等于输入总数。
9. 列表和详情是否引用同一个问题编号及结论。

如果任何检查不通过，先修正报告。不能通过只写总数或合并说明来绕过逐项输出要求。

## 6. 超长清单

清单较长时可以分批分析、分段组织报告，但最终交付仍必须包含完整清单的全部独立结果。不得因上下文或篇幅限制而静默省略。若确实无法完成全部核实，应对尚未核实的问题逐项输出 Unverified，并说明限制，仍保持一一对应。
