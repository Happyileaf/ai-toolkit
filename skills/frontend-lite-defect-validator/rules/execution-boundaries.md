# 执行边界

## 1. 允许的操作

- 阅读输入问题清单和相关项目代码。
- 查看相关类型、配置、调用方、被调用方及共享封装。
- 阅读相关测试。
- 在必要且成本合理时执行局部测试。
- 生成独立的核实报告。

## 2. 禁止的操作

- 修改业务代码。
- 修改测试代码。
- 修改项目配置或依赖。
- 修改、覆盖或重写原始问题清单。
- 自动修复问题或生成代码补丁。
- 执行与核实无关的重构、格式化或清理。
- 主动扩展为全项目缺陷扫描。
- 生成修复计划、下游任务或工作流。
- 指导下游如何消费或处理核实报告。

## 3. 测试边界

局部测试仅用于帮助判断当前输入问题：
- 优先复用已有测试。
- 不默认运行完整测试套件。
- 不为了运行测试安装新依赖或修改配置。
- 如测试命令会产生文件、访问外部系统或修改环境状态，先评估必要性和影响；不适合安全执行时不运行。
- 不能因测试失败就自动修改代码。

## 4. 项目上下文边界

只读取判断当前问题所需的最小上下文。若问题依赖不可访问的服务端实现、外部依赖或业务资料，说明具体缺失内容并酌情标记 Unverified。

在相关上下文中发现输入清单以外的问题，不主动分析或报告为新的问题。

## 5. 输出边界

报告只呈现输入问题的核实结果、必要证据和判断理由。可以提供简洁的结果统计，但不提供修复工作流、后续任务建议或下游消费指导。
