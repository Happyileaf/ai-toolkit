# 问题核实报告模板

报告必须包含以下两个主要部分，顺序固定：问题确认列表、问题确认详情。

## 一、问题确认列表（Validation Summary）

### 1. 核实概览

- Confirmed：
- Likely：
- Unverified：
- False Positive：

校验：四类 Verdict 数量之和必须等于输入问题总数。

### 2. 问题列表

| No. | Original ID | Original Issue | Verdict | Confidence | Conclusion | Related Issues |
|---|---|---|---|---|---|---|
| 01 | | | | | | |

规则：
- 每个输入问题独占一行。
- 按输入顺序输出。
- 保留原始 ID；如无原始 ID，使用报告编号。
- Conclusion 简明说明核实结论。
- Related Issues 仅用于提示关联，不代表合并。
- 不得只列出 Confirmed 或 Likely；四种 Verdict 必须全部列出。

## 二、问题确认详情（Validation Details）

按照输入顺序，为每个输入问题输出一份独立详情。

### 01. 问题标题

- Report No.：
- Original ID：
- Verdict：
- Confidence：
- Related Issues：

#### 原始问题

保留原始问题主张的核心含义；不要悄悄改写原始结论。

#### 核实过程

简述实际检查了哪些文件、函数、调用关系、状态和业务约束。只记录真实执行的检查。

#### 核实依据

列出具体代码位置、执行路径、已有保护机制或测试证据。区分代码事实和分析推断。

#### 判断理由

说明证据如何支持当前 Verdict：
- Confirmed：说明触发路径、违反的预期和实际影响。
- Likely：说明已确认的风险，以及缺少的关键验证。
- Unverified：说明缺失信息或阻碍，以及其对判断的影响。
- False Positive：说明具体反证如何否定原始主张。

#### 测试验证（如执行）

- 测试命令或方式：
- 覆盖范围：
- 结果：Passed / Failed / Partial / Not Run

未执行测试时可省略本节，不得虚构结果。

#### 关联问题（如有）

列出相同根因、重复描述或相关问题的报告编号，并说明关联性质。无论是否有关联，本条问题仍需独立给出完整 Verdict。

## 三、交付前完整性检查

- [ ] 输入问题总数与问题列表记录数一致。
- [ ] 输入问题总数与详情数量一致。
- [ ] 每个原始 ID 恰好对应一条列表记录和一份详情。
- [ ] 无原始 ID 的问题按输入位置完整映射。
- [ ] 没有遗漏、重复或合并问题。
- [ ] 列表与详情的 Verdict、Confidence 一致。
- [ ] 四类 Verdict 数量之和等于输入总数。
- [ ] 关联关系没有替代独立核实结果。
