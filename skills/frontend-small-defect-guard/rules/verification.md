# Verification Rules

## 1. 验证等级

按项目能力和缺陷性质选择，不要求每次执行所有等级。

| Level | 名称 | 说明 |
|---|---|---|
| V1 | Static Inspection | 阅读代码路径、状态转换、依赖和 Diff |
| V2 | Existing Tests | 运行已有相关测试 |
| V3 | Targeted Tests | 新增或运行针对缺陷的局部测试 |
| V4 | Runtime Verification | 在浏览器或运行环境中验证真实行为 |

## 2. 验证状态

- Passed：实际执行且通过。
- Failed：实际执行且失败。
- Partial：只验证部分条件。
- Not Verified：未执行或环境不支持。

未执行测试不得描述为 Passed。测试命令启动失败也不能描述为测试通过。

## 3. 场景验收要求

场景文件必须给出可观察的验收条件。至少覆盖：
- 原始缺陷触发路径。
- 修复后的正确行为。
- 相关边界或竞态条件。
- 不应改变的既有业务行为。

## 4. 修复后检查

1. 检查修复是否真正覆盖根因，而非仅隐藏表象。
2. 检查是否引入新的竞态、状态残留或资源泄漏。
3. 检查业务代码 Diff 是否严格符合批准范围。
4. 检查局部测试是否能在修复前失败、修复后通过（条件允许时）。
5. 记录未执行的验证及其原因。

## 5. 最终结论

根据实际结果使用：
- Verified：必要验证通过。
- Partially Verified：修复已完成但验证不完整。
- Verification Failed：验证失败。
- Not Verified：没有足够验证证据。

不得用“已修复”掩盖验证失败或未验证状态。
