# 质量检查清单与完成标准

## 一、必需检查项

### 来源覆盖
- [ ] 所有输入资料均已登记。
- [ ] 每个有意义的资料单元均有覆盖状态。
- [ ] 每个已分析单元都有提取结果或明确的排除处理结果。
- [ ] 部分分析、失败和未分析的单元均说明受影响范围和原因。
- [ ] 没有仅因登记或查看大纲就将来源认定为已分析。
- [ ] 主文档中能找到来源范围、覆盖结论和未完成部分；必要的逐项明细可在 references/ 中定位。

### 需求覆盖
- [ ] 每条需求信息都有输出映射。
- [ ] included 的目标位置确实存在。
- [ ] merged 映射保留所有参与合并的需求 ID 和条件。
- [ ] referenced 映射指向主文档中的统一规则，或主文档明确链接的有效子文档。
- [ ] excluded 记录了排除原因。
- [ ] pending 已出现在主文档的待确认事项和质量结论中。

### 输出依据
- [ ] 主文档和所有被主文档引用的子文档中的每项正式需求都有一个或多个有效来源引用。
- [ ] 推断说明了依据，并持续标记为 inferred。
- [ ] 不确定和冲突内容仍然明确处于未解决状态。
- [ ] 技术说明与产品需求分开。
- [ ] 没有将资料未说明的交互或业务规则写成已确认需求。

### 一致性与链接
- [ ] ID 唯一且稳定。
- [ ] 引用的来源 ID 和需求 ID 均存在。
- [ ] 依赖关系能够解析，或明确标记为外部依赖。
- [ ] 输出路径和锚点有效。
- [ ] 需求清单与最终文档中的确定性、前端相关性、范围和映射状态一致。
- [ ] 合并/引用后的内容没有丢失重要条件。
- [ ] 每个 references/ 子文档都能从主文档到达，且没有孤立子文档。

### 文档可用性
- [ ] frontend-requirements.md 存在，并且是唯一明确的最终需求文档入口。
- [ ] 默认需求内容（包括各业务模块和共享规则）直接组织在主文档中。
- [ ] 没有仅因业务模块数量、模块边界或目录整齐而拆分文件。
- [ ] 不默认创建 analysis/、requirements/ 或 README.md 等并列文件。
- [ ] 只有存在明确必要性时才创建 references/ 子文档。
- [ ] 主文档保留整体结构、核心说明和拆分内容的入口，不是单纯目录索引。
- [ ] 最终需求按业务模块组织。
- [ ] 包含必要的业务上下文。
- [ ] 页面、功能、共享规则和跨页面行为的归属合理。
- [ ] 在来源有定义的情况下，覆盖角色、权限、状态、数据依赖和异常。
- [ ] 待确认事项易于发现，并关联到受影响的需求。
- [ ] 术语保持一致。

## 二、明确的核验步骤

1. 遍历来源索引和来源单元台账。
2. 逐项核对覆盖记录及其处理结果。
3. 遍历每条需求信息，核对其输出映射。
4. 遍历主文档及其引用的所有子文档中的正式需求，核对来源依据或显式状态。
5. 对照需求清单和最终文档，检查状态字段是否一致。
6. 验证所有 ID、依赖、路径和锚点。
7. 检查主文档是否可独立阅读、references/ 是否确有必要，以及所有子文档是否均可从主文档到达。
8. 在质量报告中记录失败项、接受的限制和未解决决策。默认将结论整合到主文档；只有明细过长或确有独立维护价值时才拆分。

不得以笼统的自我评价或抽样检查代替逐项核验。如果资料规模超过当前工具/上下文能够完整核验的范围，必须披露具体未检查部分，并将覆盖状态标记为部分完成。

## 三、异常严重程度

| 级别 | 含义 |
|---|---|
| blocker | 关键输入无法识别或读取，导致无法有效分析目标或核心需求 |
| high | 关键业务规则冲突、关键模块未分析，或正式需求缺少依据 |
| medium | 映射缺失、重要上下文缺失或引用失效，影响需求理解 |
| low | 非关键定位精度、措辞或组织问题 |

异常记录应包含 issue_id、check_layer、severity、related_ids、description、impact、recommended_action 和 status（open、resolved、accepted-limitation）。

## 四、完成状态

- **Completed（已完成）**：三层追溯和一致性检查均已执行，没有未披露的高风险问题。
- **Completed with issues（存在问题但已完成）**：主要分析和检查已完成，但仍存在待确认问题、部分覆盖或其他已披露问题。
- **Incomplete（未完成）**：关键资料无法读取、关键分析阶段未完成，或无法可靠执行必要的追溯检查。

存在问题不妨碍一次分析完成，但绝不能为了得到 Completed 而隐藏、弱化或强行解决问题。

## 五、计数与覆盖率

只有在分母和计数规则明确时，数量统计才有意义。避免主观完整度评分或缺少依据的百分比。如果无法基于明确的资料单元/需求记录集合计算百分比，就不要报告百分比。
