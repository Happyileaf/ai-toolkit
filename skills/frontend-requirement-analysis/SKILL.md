# Frontend Requirement Analysis

> **当前状态：设计阶段。** 本文件先建立 Skill 入口和基本边界，不代表完整执行能力已经实现。后续实现应以本目录下的三份正式设计文档为准。

## 目标

从前端开发人员的工作视角出发，对完整产品 PRD 及相关资料进行分析、筛选、关联和重构，交付：

1. 一套可追溯的需求分析资料，用于记录输入资料、分析结果、需求清单、信息关联、待确认事项和质量检查。
2. 一份按业务模块组织、能够独立帮助前端开发人员理解工作范围和需求行为的前端需求文档。

产物是连接产品需求与前端研发工作的中间文档，不是 PRD 摘要，也不是前端技术设计方案。

## 核心原则

- 以完整资料为分析对象，不只摘录标题或关键词。
- 以业务模块组织最终需求；模块内部按页面、功能和共享规则组织。
- 保留前端实现所需的业务上下文，即使该信息本身不由前端实现。
- 区分明确事实、合理推断、信息不确定和资料冲突。
- 不擅自补充产品交互、业务规则或产品决策。
- 不因 PRD 未提及某项功能，就推断该功能不存在或不在本次范围。
- 每条被保留的需求都应有明确处理去向；每项正式需求都应有来源依据。
- 原始资料、需求清单和最终文档之间必须建立三层追溯与覆盖闭环。
- 分析过程应透明披露资料缺失、读取失败、冲突和未解决问题。
