# 前端开发规范入口（分片版）

本文件只做入口、路由和总门禁，不承载全部细则。每次前端修改都必须先读本文件，再按本次触发维度读取 `.harness/docs/frontend/rules/` 下的分片规则。不要默认加载全部分片，避免上下文过长导致遗漏。

## 1. 适用范围

- 修改页面、组件、路由、状态流、样式系统、请求层、测试或脚手架。
- 变更用户交互行为、可访问性、性能预算或发布质量门禁。
- 涉及跨页面流程、权限控制、缓存策略、埋点和监控。

## 2. 触发维度与规则分片

| 触发维度 | 典型场景 | 读取规则 |
| --- | --- | --- |
| 通用工程 | 任意前端代码、配置、脚本变更 | `.harness/docs/frontend/rules/00-core.md` |
| 状态与数据流 | store、hooks、缓存、派生状态、表单状态 | `.harness/docs/frontend/rules/state-and-dataflow.md` |
| UI/UX 与可访问性 | 页面结构、组件交互、样式与语义标签 | `.harness/docs/frontend/rules/ui-ux-a11y.md` |
| 网络与安全 | API 调用、鉴权、错误处理、环境配置 | `.harness/docs/frontend/rules/network-and-security.md` |
| 测试与发布 | lint/typecheck/unit/e2e、门禁策略、回归范围 | `.harness/docs/frontend/rules/testing-and-release.md` |
| 性能与可观测 | 包体、渲染性能、关键指标、日志埋点 | `.harness/docs/frontend/rules/performance-and-observability.md` |

## 3. 总门禁（每次前端修改必须满足）

所有前端修改都必须在 build 前复述并在 qa 中核对以下 5 条总门禁：

1. **先契约后实现**：必须先有 spec/contract；若缺少前端门禁声明，先补齐再编码。
2. **先复用后新增**：先查本地已有组件、hooks、样式 token、请求封装和状态层；如无必要，不新增并行体系。
3. **关键体验不退化**：响应式、可访问性、状态流（加载/空/错）不可缺失。
4. **可验证可回归**：lint/typecheck/unit/build 必须可执行；required 场景必须有 e2e 或人工证据。
5. **发布可控可回滚**：风险改动必须有灰度与回滚说明，且在 QA 报告中记录。

## 4. 维度门禁最小清单

### 4.1 通用工程门禁

1. 无无关重构、无关格式化和范围外改动。
2. 关键常量、配置 key、设计 token 不散落魔法值。
3. 调试残留（`console.log`、`debugger`、临时注释逻辑）必须清理。
4. 新增函数/方法补齐中文注释（用途、参数、返回值、副作用）。
5. 改动文件可追溯到 contract 验收项。

### 4.2 交互与可访问性门禁

1. 关键操作可键盘触达。
2. 非装饰性图片具备可读 `alt`。
3. 表单输入、错误提示和禁用状态可感知。
4. 移动与桌面关键断点可用。
5. 不破坏已有导航、焦点顺序和语义结构。

### 4.3 状态与数据流门禁

1. 不重复维护同一业务状态来源。
2. 异步请求具备加载态、成功态、失败态和取消/超时处理。
3. 缓存失效策略明确（何时命中、何时重取、何时清理）。
4. 副作用不泄漏（订阅、计时器、事件监听可清理）。
5. 错误状态对用户可见且可恢复。

### 4.4 网络与安全门禁

1. 禁止硬编码 token、秘钥、生产 URL。
2. 请求层统一处理鉴权、超时、重试和错误映射。
3. 不在关键路径直接读写本地存储且无兜底。
4. 配置差异通过 env/config 管理，不在业务代码散落分支。
5. 异常信息对外脱敏，不暴露内部实现细节。

### 4.5 测试与发布门禁

1. `convention-check` 无 FAIL；WARN 修复或解释。
2. lint/typecheck/unit/build 通过。
3. required 场景 e2e 或人工验证通过并留证据。
4. QA 报告与 gate result JSON 归档完整。
5. required 门禁未通过不得标记 `passes=true`。

## 5. 建议执行顺序

1. 读取 `00-core`。
2. 按任务触发维度读取对应分片。
3. 在 spec/contract 中写明适用规则、不适用原因和人工确认项。
4. build 阶段逐条自检，qa 阶段逐条评分。
