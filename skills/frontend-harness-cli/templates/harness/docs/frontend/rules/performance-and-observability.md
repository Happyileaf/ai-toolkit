# 性能与可观测规则

本文件适用于包体、渲染性能、关键指标和埋点监控相关改动。

## 1. 触发条件

- 新增重组件、复杂列表、动画、大体积依赖或长链路请求。
- 修改首屏渲染、分包策略、懒加载、缓存策略。
- 新增或修改埋点、日志、监控告警。

## 2. 核心门禁

1. **性能预算明确**：首屏、交互延迟、包体预算有目标值。
2. **渲染成本可控**：避免不必要重渲染和大对象频繁创建。
3. **依赖增长可解释**：新增依赖需说明收益与替代方案。
4. **可观测可定位**：关键失败路径具备日志或埋点证据。
5. **降级可执行**：异常场景存在降级或兜底方案。

## 3. 实施建议

- 优先按需加载，避免一次性拉入大型依赖。
- 列表渲染使用稳定 key，避免 index key 导致状态错位。
- 把关键性能指标与回归阈值写入 contract。
- 对关键链路添加最少必要埋点，避免噪音日志。

## 4. 验收证据

- contract 明确性能预算与验证方式（build 报告、手测、监控数据）。
- QA 报告记录关键性能指标是否达标。
- 若未达标，给出风险说明、缓解措施和后续任务。
