# 前端通用工程规则

本文件适用于所有前端任务。每次前端修改都必须先读取本文件；只有触发具体维度时，才继续读取其他分片规则。

## 1. 触发条件

- 修改前端业务代码、样式、配置、脚本或工程结构。
- 修改组件、页面、路由、状态层、请求层。
- 增加或调整测试、构建、门禁脚本。

## 2. 核心门禁（每次前端修改必须满足）

1. **先读契约再编码**：编码前必须读取当前任务 `spec/contract` 与规范入口。
2. **先看本地实现**：新增模式前必须查看同层既有实现，优先复用。
3. **范围可追溯**：每个改动文件都要映射到 contract 验收项。
4. **体验不降级**：响应式、可访问性、状态流不允许空缺。
5. **结果可复现**：lint/typecheck/unit/build/e2e 的命令和结果可复现。

## 3. 编码前检查清单

1. 当前 `spec/contract` 已覆盖本次前端总门禁与触发分片规则。
2. 关键风险（兼容性、性能、可访问性、回滚）已在 contract 记录。
3. 已确认可复用组件、hooks、样式 token、状态层和请求封装。
4. 新增抽象的必要性、替代方案和回滚影响已写入 contract。
5. 验证方式（unit/e2e/manual）明确且可执行。

## 4. 禁止事项

- 禁止范围外修改、顺手重构和无关格式化。
- 禁止在业务代码中硬编码生产 URL、token、秘钥。
- 禁止关键交互只支持鼠标，不支持键盘访问。
- 禁止样式散落魔法值，忽略既有 design token/CSS 变量体系。
- 禁止带调试残留（`console.log`、`debugger`、临时禁用逻辑）收口。

## 5. 完成定义

前端任务只有同时满足下面条件，才算完成：

- contract 验收标准全部有结果。
- `convention-check` 无 FAIL。
- lint/typecheck/unit/build 通过。
- required 场景验证通过（e2e 或人工证据）。
- QA 报告与 result JSON 已归档。
