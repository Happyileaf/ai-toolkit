# 状态与数据流规则

本文件适用于 store、hooks、缓存、异步数据加载与表单状态相关改动。

## 1. 触发条件

- 新增或调整全局/局部状态管理。
- 新增异步请求流程、缓存策略或表单状态。
- 修改派生状态、状态同步逻辑或副作用链路。

## 2. 核心门禁

1. **单一状态来源**：同一业务语义只允许一个权威来源。
2. **状态可解释**：加载、成功、空、错误、重试状态必须可区分。
3. **副作用可清理**：订阅、定时器、监听器必须销毁。
4. **并发可控**：请求竞态、重复提交、过期响应要有处理策略。
5. **回滚可控**：状态变更失败后可恢复到安全状态。

## 3. 实施建议

- 优先复用项目既有数据获取层与缓存策略。
- 异步状态采用显式枚举或语义常量，不用裸字符串拼状态。
- 表单提交应包含禁用态、防重入和错误提示。
- 关键状态迁移建议补单元测试或状态机断言。

## 4. 验收证据

- 状态流图或关键状态转移说明已记录在 contract。
- unit 测试覆盖关键分支（成功/失败/重试/取消）。
- QA 报告包含异常场景复现结果。
