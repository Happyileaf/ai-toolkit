# 网络与安全规则

本文件适用于请求层、鉴权、配置、错误处理和前端安全相关改动。

## 1. 触发条件

- 新增或修改 API 调用、请求封装、错误映射。
- 修改登录态、权限判断、token 刷新、会话存储。
- 修改环境配置、域名策略、代理或跨域处理。

## 2. 核心门禁

1. **配置集中化**：环境差异必须走配置层，不散落业务代码。
2. **凭据安全**：禁止硬编码 token、secret、apikey。
3. **错误可恢复**：网络失败、超时、鉴权失败有统一处理和用户提示。
4. **存储有兜底**：本地存储不可用时有异常处理路径。
5. **信息不泄露**：错误信息对外脱敏，不暴露内部细节。

## 3. 实施建议

- 请求层统一注入 headers、超时、重试、trace 标记。
- 对幂等请求和非幂等请求采用不同重试策略。
- 关键失败要有 fallback 或重试入口，避免页面“静默失败”。
- 统一错误码映射为用户可理解提示与内部可定位日志。

## 4. 验收证据

- contract 中声明关键接口的成功/失败断言。
- unit 或 e2e 覆盖超时、401、500 等异常路径。
- QA 报告包含错误提示与恢复路径验证结果。
