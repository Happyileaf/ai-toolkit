# 知识整理

在编写文档之前，将发现的信息整合为一致的分析模型。

分析模型应包含：

- Repository 和项目类型。
- 系统目标、范围、运行环境和调用方。
- 入口与生命周期。
- 分层、模块、职责和依赖关系。
- Public interfaces 和重要 contracts。
- 数据实体、状态、持久化和转换过程。
- 重要业务、运行时和运维流程。
- 外部系统及集成边界。
- 领域词汇和技术概念。
- 证据引用、可信度和未解决问题。

为每个模块和概念确定唯一的标准名称。区分直接依赖与间接关系，也要区分观察到的事实与分析解释。遇到矛盾时，回到源码证据核实；如果仍无法确认，则明确记录不确定性。
