# Diagram Conventions

- Store editable Mermaid source in `.mmd` files under `docs/analysis/diagrams/`.
- Use architecture diagrams for components, layers, dependencies, and external boundaries.
- Use sequence diagrams for time-ordered interactions and flowcharts for decisions or branching logic.
- Use consistent names with the written documentation.
- Label arrows with meaningful actions, data, or protocols.
- Keep each diagram focused; split unrelated concerns into separate diagrams.
- Do not imply a dependency, call, or sequence that source evidence does not support.
- Include a short caption or explanation in the relevant Markdown document.
- Avoid code-level diagrams unless they materially clarify complex behavior.
