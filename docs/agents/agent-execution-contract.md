# Agent 执行契约

> 本文件定义 Agent 在本仓库执行任务时的行为门禁与范围控制，是所有冲突的最终裁决依据。

## 1. 行为门禁

### 1.1 开始前必做

- 显式列出本轮的：假设、歧义、取舍、范围外事项。
- 默认用户输入已确认，不反复澄清；如确有阻断性歧义，使用 `AskUserQuestion` 一次性批量提问。
- 阅读相关代码后再改动，禁止凭命名猜测修改。

### 1.2 实现原则

- **最小实现**：默认选择满足验收标准的最小实现。
- **范围受控**：禁止隐式扩范围、顺手重构、相邻格式化。每个改动文件必须能追溯到需求范围或修复项。
- **只清理本论改动制造的问题**，不主动处理无关历史问题。
- **不创建非必要文件**：优先编辑现有文件，禁止主动创建文档/README。
- **不过度设计**：不加未要求的功能、配置项、抽象层；三段相似代码胜于过早抽象。

### 1.3 提交前自检

- lint / typecheck / unit / build / e2e（按 contract 要求）。
- 验收标准逐条核对。
- 无调试残留（`console.log`、`debugger`、TODO 等）。
- 改动文件清单与范围一致。

## 2. 执行循环

任何非平凡改动遵循以下顺序，**不得跳步**：

1. **理解**：读取需求/spec/相关代码，列出假设与范围外事项。
2. **设计**（如需要）：编写 spec，含组件边界、验收标准、边界场景（至少 3 个）。
3. **实现**：按 spec 范围最小实现。
4. **自检**：运行检查 + 验收标准逐条核对。
5. **提交**：按 Conventional Commits 规范提交（行业标准，不另立文档）。

## 3. 范围控制

### 3.1 允许的范围

- 需求/spec/contract 明确列出的功能点。
- 为实现上述功能点必须的直接改动。
- 本轮改动直接引入的回归修复。

### 3.2 禁止的范围

- 顺手重构无关模块。
- 相邻格式化（除非改动行本就需要格式化）。
- 未被要求的性能优化、类型补全、注释补充。
- 删除看似未使用的代码（除非确认无引用）。

### 3.3 范围外发现的处理

- 若发现范围外问题，记录到本轮报告的"建议"区，不在本轮处理。
- 若该问题阻断当前范围，明确告知用户并等待指示。

## 4. 失败处理

- 检查或测试失败：先定位根因，不盲目重试。
- 同一错误连续 3 次未解决：停止重试，向用户报告现状与可选路径。
- 禁止用 `--no-verify` 跳过 hooks，除非用户明确要求。

## 5. 文档新鲜度

- 改动涉及公开 API、目录结构、配置项时，同步更新对应文档。
- 文档更新作为本轮改动的一部分，不单独提交。
- 文档与代码冲突时，以代码为准并当日修复文档。

## 6. 与其他子文件的关系

- 本文件是行为层裁决依据。
- 与本目录其他文件冲突时，以本文件为准。
- 通用技术规范遵循行业标准，不另立文档（见 [`AGENTS.md`](./AGENTS.md) 的"通用规范"一节）。
